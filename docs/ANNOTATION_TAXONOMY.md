# Timing annotation taxonomy

This is the design outcome for #1092. A timeline annotation is not a general-purpose shape registry: canonical types are added only when they own meaning or behavior that existing entities cannot express.

| Candidate | Canonical meaning and time anchors | Checker / Problems relation | Presentation and export | Decision |
| --- | --- | --- | --- | --- |
| Delay / latency | An observed elapsed interval is a `measurement` with two semantic anchors. A required/allowed latency is a `latency` Constraint with trigger/response Signal IDs, edges, and min/max cycles. | The Constraint produces a Problem when a concrete sequence violates its bound; a Measurement records/exports the observed value and does not itself pass/fail. | Reuse Measurement geometry and existing latency Constraint/Problem workflow. Native document Save/Open retains canonical data; SVG/PDF is visual output and does not round-trip Constraint semantics. | MERGE into Measurement or latency Constraint according to intent. No `delay` Annotation type. |
| Setup window | A bound on data stability before a clock/capture edge. It owns a data transition anchor, a capture edge anchor, and a required cycle/time interval. | A typed Setup Constraint checks the interval and emits a navigable Problem on violation. | Show the rule through Constraint editing and Problems; an optional generated region is a projection, not separately authored canonical truth. Native Save/Open preserves the rule; SVG/PDF may show its interval but is not a semantic round-trip format. | KEEP as a distinct Constraint rule; child #1119. |
| Hold window | A bound on data stability after a clock/capture edge. It owns a capture edge anchor, a following data transition anchor, and a required interval. | A typed Hold Constraint checks the interval and emits a navigable Problem on violation. | Same projection/export policy as Setup. Do not model Hold as an independent rectangle with duplicated endpoints. Native Save/Open preserves the rule; SVG/PDF may show its interval but is not a semantic round-trip format. | KEEP as a distinct Constraint rule; child #1119. |
| Valid window | A visual interval indicating where a value is meaningful. It has no independent checker semantics by itself. | If a protocol rule is intended, encode that rule as a Constraint; a Highlight/Timing Region alone is not a pass/fail rule. | Reuse Highlight or Timing Region anchors and existing export. | MERGE into existing presentation types; no new canonical type. |
| Don't care | An authored wildcard/mask for comparison is checker semantics, not a drawing primitive. It must not overwrite a Signal's actual 0/1/x/z value. | Could become a typed comparison-rule/mask input; Problems are derived from comparing against it. | Existing Highlight may visually identify a range but does not carry don't-care meaning. Save/Open and export must preserve a future rule if approved. | DROP as an Annotation type; defer checker-mask semantics to a dedicated product issue. |
| Expected | The expected waveform is already the canonical Signal transition sequence. | Existing checks compare actual/derived data against authored Signal values and Constraints. | Rendered as the waveform; a duplicate overlay would create a second source of truth. | DROP as an Annotation type. |
| Error / Warning | A diagnostic classification and severity, not an authored time-span entity. | Use `DocumentProblem`/Problems with severity, operation, object identity, and source time. | Reveal/navigation targets the affected entity/cycle; no separate export annotation. | MERGE into Problems. |
| Cause / Effect | A relationship between semantic entities, not a time geometry of its own. | A typed Constraint or protocol rule can validate the relationship and emit Problems. | Reuse `dependency` presentation where a visible relationship is useful; export that existing type. | MERGE into Constraint and/or dependency Annotation according to behavior. |
| Protocol violation | A derived result of evaluating protocol/Handshake/Constraint semantics. | Represent as a Problem linked to the Constraint and affected Signal/time. | Reveal the existing waveform/constraint; do not save a second authored violation Annotation. | MERGE into Problems. |
| Requirement | Traceability metadata linking a specification obligation to semantic entities; it is not inherently a time interval. | A linked Constraint may verify the obligation; Problems report its failed evaluation. | A future requirement-management surface can link stable IDs. Do not encode requirement prose as a fake time annotation. | DROP from this annotation taxonomy; any traceability system requires its own product issue. |

## Shared persistence and command policy

- Existing Measurement, Constraint, Signal, Annotation, and Problem ownership remains authoritative. A new shape is never a parallel source of timing truth.
- Canonical semantic data is saved/opened and participates in Undo/Redo through typed SemanticCommands. Derived Problems and generated Constraint regions are recomputed and are not separately authored state.
- Existing supported Annotation and Measurement presentation is exported through the current visual export. SVG/PDF is not a semantic round-trip format: Constraint rules remain canonical in `.tcd`; any exported Setup/Hold interval is a derived visual cue, not executable checker data.
- AI may create or edit only through an existing typed SemanticCommand. A new Constraint rule is unavailable to AI until its schema, command, validation, and round-trip support land together in its child issue.
- View-only presentation changes do not affect Canonical, History, or Dirty.

## Approved implementation boundary

Only Setup and Hold remain new semantic work in this candidate set. They share the existing Constraint owner but need distinct typed rule contracts and validation. Implement them in bounded child #1119. The other candidates reuse existing owners or are excluded from annotation semantics; no enum expansion is approved for them.
